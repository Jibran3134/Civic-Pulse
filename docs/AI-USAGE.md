### Residual risk

* The retry `for` loop in both providers now reads `self._max_retries` from
  settings at construction time.  If `lru_cache` returns a stale `Settings`
  object (possible in tests that patch env vars), retries will reflect the
  cached value.  Tests override `_max_retries` directly on the instance to
  avoid this.
* `triage_cache_ttl_hours` is stored in `Settings` but `triage.py` still
  hard-codes `ttl=86400` in the `cache.set` call.  A follow-up task should
  read `settings.triage_cache_ttl_hours * 3600` there.  This was left
  out-of-scope to avoid touching code that belongs to an in-flight PR.
